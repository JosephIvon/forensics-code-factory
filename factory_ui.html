拆解方法

对 JD 的 11 条职责 + 10 条任职要求，按两维打分：商业价值（该能力在岗位中的稀缺度/成本）与 AI 可替代性（纯文本变换 vs 必须现场硬件）。两维皆高者即智能体切入点。

实测结果（本机复验过的部分，与未验证部分分开写）

  • 编译级验证（csc）：固高 / 雷赛 / 正运动 / 全品牌套件（含软赢+高川骨架）= 0 错误 0 警告。早期单独生成的软赢/高川骨架套件带 2 条 CS0162，已随修复版重新生成。
  • 运行级验证：仅 VirtualController 仿真路径被真正执行过（回零 → 插补走胶/IO 时序 → 圆弧 → DI 互锁 → 力控 → SPC/Cpk，PASS，退出码 0）。各品牌适配器的 P/Invoke 路径只做了编译级验证，从未运行——须真机。
  • 外部证据：Modbus CRC16 用标准测试向量 0x4B37 校验通过（向量独立于生成逻辑）。适配器 SDK 签名已接入官方真值核对（PE 导出表 + 官方 C# 绑定 / C 头文件，见 Tab4 诚实边界）。

诚实边界（KB 级别制 + 证据分级）

    
    
      
  • A 级 虚拟控制器：100% 自研，编译+运行均已验证（跟随误差/噪声/固定种子仿真）
    • 
      
  • B 级 固高/雷赛/正运动/ACS：架构/线程/单位换算/错误映射为工程级成品，仅编译级验证。SDK 函数名与参数表已按官方真值（PE 导出表 + 官方 C# 绑定 / C 头文件）逐条核对，并可用核对工具回归；仍带 [核对] 标记的项（单位/量程/IO 极性/回零模式号）须按厂商手册确认。ACS 另需厂商 DLL，不在全品牌套件内
    • 
      
  • C 级 软赢/高川：骨架 + TODO 清单（获取手册后按同构模式补全）
    • 
      
  • 核对清单的循环性：ApiChecklist.md 由同一知识库生成——它能告诉你"去哪核对"，不能发现"生成错了"。签名的唯一有效依据是厂商官方手册/头文件，比对工时按手册篇幅实估，本工具不做工时承诺
    • 
    

    
真实定位：AI 消灭的是架构与样板代码的工时（这部分可直接编译验证）；SDK 签名的正确性属于外部证据问题，AI 生成不构成证据，只能靠人工对照手册。
