# 前言：为什么这本书敢把每个主张都锚到「仓库@commit + 路径 + 行号」上

> 本卷讲一个仓：**上位机代码工厂**。它做的事说起来一句话——厂商手册进知识库，
> 生成器读知识库产出可编译工程。难的不是生成，是**凭什么信生成出来的东西**。

## 一、这本书要证伪的那件事

工程写作里最常见的失效不是写错，是**写得没法核**。

「系统支持多品牌运动控制」「P/Invoke 签名已全部核对」——这类句子读起来都对，
但读者没法当场验证：支持几个品牌？哪几个？核对到哪一步？谁核的？核的是哪一版？

所以本卷的规矩只有一条：

> **凡是事实性句子，必须挂一个坐标；凡是坐标，必须能被第三方当场打开。**

坐标的形状是 `仓库@commit + 路径 + 行号`，例如
`trae_factory@954c210 gen/adapters_kb.js:37`。读者 `git clone` 本仓、
`git show 954c210:gen/adapters_kb.js`，第 37 行就在那里。

这不是修辞上的严谨，是**可证伪**：任何一条断言，只要坐标打不开或者打开后不是那个意思，
它就当场破了。这本书里所有的「已核」「全过」「0 条」，都是这么被钉住的。

## 二、锚点为什么落在本仓

2026-10-24 之前，这本书与它的代码**不在一个仓里**：书在书仓，代码在
`trae_factory`。那带来一个具体的问题——

书里每一处坐标都指向代码仓的某个提交。读者手里只有书，没有那个提交；
于是「当场可核」这句话就只剩下作者自己能兑现。**一本书要求读者相信一件他无法验证的事，
它教的就正好是它反对的东西。**

因此本卷搬迁：**书搬进代码仓**，锚点改成**本仓自己的某一次提交**。

| 项 | 值 |
|---|---|
| 锚点提交 | `954c210`（本卷的停机点，在本仓历史里） |
| 锚点在正文里的写法 | `trae_factory@954c210` |
| 定义处 | `book/tools/_anchor.py`（**全书只此一处**） |

坐标前半截的 `trae_factory` 是**项目标识**，不是目录名。本仓的目录名与 GitHub 仓名是
`forensics-code-factory`（2026-10-24 从 `trae_factory` 改名而来）。两者是两层东西：
一个指**磁盘上的哪个目录**，一个指**这本书在讲哪个项目**。仓根 `README.md` 的
「仓名对照」一节记着这件事。

## 三、这一卷在四章里讲什么

四章，不是九章。这不是没写完，是**这卷要讲的事本来就少**：
四章各自立住一条主张，说完了就停；凑章数会把同一件事拆成两遍讲，
读者多花时间，得到的判断反而更少。

| 章 | 一句话 | 它证伪的常见说法 |
|---|---|---|
| 第 1 章 代码工厂 | 知识库驱动的生成，换卡=改一个枚举 | 「多品牌支持」= 一份代码改改就能用 |
| 第 2 章 真值链 | 每条生成出来的声明挂三根轴：源｜核对｜提取 | 「编译通过」= 签名正确 |
| 第 3 章 手册进知识库 | 手册是入口不是真值；查不到时怎么不编 | 「手册里有」= 我照着写了 |
| 第 4 章 双仓收尾实录 | 把悬着的状态逼成入库/忽略/挂起三类 | 「差不多了」= 可以交付了 |

**章号不是阅读顺序**。第 3 章是第 1 章的上游（知识库是生成器的食粮），
所以建议按 **3 → 1 → 2 → 4** 读一遍；第 4 章是全卷的收口。

本卷是《取证式学习》三册里的第三册。另外两册讲的是别的仓，
本书中引用它们时写明书名（《协议域卷》《审计与合规卷》），
本卷可以单独读完——那些跨册引用是**延伸**，不是前置。

## 四、这本书不承诺什么

诚实账要写在前面，不能只写在结尾：

- **不承诺覆盖全部实现**。四章讲的是骨架与纪律，不是 API 手册。
  仓里还有生成器的具体模板、五家品牌各自的适配细节，书里只挑能撑起主张的部分。
- **不承诺已跑完真机**。P/Invoke 的签名真值靠三层官方物证对撞，这是**纸面与二进制**层面的核对；
  真机层在设计上就是**挂起**的（第 4 章记了这条挂起是怎么登记的）。
  挂起≠做完，书里不许把它写成做完。
- **不承诺没有债**。仓里已知的欠账（迁居凭证、外置原件、0 条 P/Invoke 的两个品牌）
  在第 4 章逐条列了，连带它们为什么不算「已清」。

## 五、怎么用这本书

| 你是 | 从哪读起 |
|---|---|
| 想用这个工厂 | 第 3 章 → 第 1 章，其余按需 |
| 想学真值链（跨仓协作、给 AI 生成物打坐标） | 第 2 章是核心，第 1、3 章是上下文 |
| 想看一份真实的交付收尾长什么样 | 直接读第 4 章——它是两个仓的活体案卷 |
| 讲师 | `crops/裁剪版.md` 里有每章的 90 分钟切分与组合方案 |

每一章的结构固定：**承接/学完你会/前置** → 概念 → 解剖与案例 → 习题 →
可验证主张框 + 讲师切分 → **证据与坐标**。最后一节是本章所有事实性句子的坐标清单，
它同时也是本章的验收单。

## 六、这本书自己怎么被验

本卷的门禁在 `book/tools/`，跑法见 `book/README.md`。它们各管一件事：

- **坐标审计**：正文里每个坐标是否能在锚点提交上打开、内容是否对得上；
- **结构门禁**：每章该有的件是否齐（承接段、习题、证据区、锚点字符串一致）；
- **裁剪件逐字**：`crops/裁剪版.md` 里每一段是否能在正文里逐字找到；
- **书里的数字**：书里自报的行数/条数是否与实算一致。

门禁红了不许合、红了不许发。**一个不报警的门禁比没有门禁更坏**——
它让人以为验过了。这条纪律在本卷里出过事（自检规则一度匹配到 0 处却照样算通过），
所以现在有一条硬规定：**门禁匹配到 0 处即判失败**，不许把空转当通过。
