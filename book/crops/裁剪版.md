# 裁剪版：四章的可验证主张与 90 分钟课切分

> **来源**：各章 §末「可验证主张框」与「讲师 90 分钟」两段原样裁剪，一字未改（2026-10-22 定版，
> 2026-10-24 并仓随本卷入仓）。本文件只做**排版合并**，不改正文任何一个字。

## 为什么只有一版

原先有**两份**裁剪件：一份只留可验证主张，一份只留 90 分钟切分。并仓时合成一份，理由有三条：

1. **两者说的是同一件事的两种用法**。一条可验证主张是被压到一句话的「事实 + 锚点」，
   讲师切分是同一批主张的**教学顺序**。分成两个文件，读者得来回翻才知道某条主张配哪段课。
2. **分开会漂移**。两份文件各抄一遍章号与 §号，改一处忘另一处，就成了两个版本的书。
   并成一份后，章号与 §号在这一个文件里各出现一次。
3. **验的是同一条**：`tools/verify_crops_verbatim.py` 要求本文件的每一段都能在正文里
   逐字找到。一份文件只有一个被验对象，比两份各自被验更不容易漏。

## 怎么用（先读这条再用）

1. **可验的含义**：锚点 = 仓库@commit + 路径，对有仓库访问权的人当场可验
   （`git clone` 本仓后开文件即对上数字）。对外引用时以本书章节 + commit 散列为证。
2. **数字全部有坐标**：可验证主张里没有形容词撑场的数字——每个都挂在
   `trae_factory@954c210` 或工件路径上；追问到底就是本卷对应章节。
   （`trae_factory` 是本仓的**项目标识**，目录名与公开仓名是 `forensics-code-factory`，
   见仓根 `README.md` 的「仓名对照」。）
3. **按岗位挑 2-3 条，勿全贴**（建议见下表）。
4. **第 4 章是双仓合册案卷**：它同时结清本仓与《审计与合规卷》的尾账，
   读者可把它当全卷收口。
