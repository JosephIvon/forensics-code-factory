# OUTLINE —— 本卷规格

> 本文件是**规格**，不是目录：它规定每一章必须交付什么、
> 坐标必须长什么样、什么情况下这一卷算完成。
> 正文在 `chapters/`，裁剪件在 `crops/`，工具在 `tools/`。
> **规格变了，正文必须跟着变**——所以本文件与正文由同一批门禁守着。

---

## 一、卷的定位

| 项 | 内容 |
|---|---|
| **对象** | 上位机代码工厂（多品牌运动控制代码生成器），**公开仓** `forensics-code-factory` |
| **锚点** | `trae_factory@954c210`（由 `tools/_anchor.py` 单点定义） |
| **读者** | 上位机工程师 / 平台开发者 / 想给 AI 生成物打坐标的人 / 讲师 |
| **不是** | 使用手册、厂商适配教程、横向评测 |
| **是** | 可复核的工程解剖：每条事实挂坐标，每条坐标可解析 |

**章数**：四章 + 导读。四章是刻意的，不是没写完——这卷要讲的事就四条，
凑章数会把同一件事拆两遍讲（见 `前言.md` §三）。

## 二、章的规格

每章固定交付十件（由 `tools/check_book_structure.py` 判）：

| # | 件 | 要求 |
|---|---|---|
| 1 | 标题 | `# 第N章 …` 开头，N 与文件序号一致 |
| 2 | 本章承接 | 章首 12 行内出现 `**本章承接**` |
| 3 | 学完你会 | 章首 12 行内出现 `**学完你会**` |
| 4 | 前置 | 章首 12 行内出现 `**前置**` |
| 5 | 素材坐标 | 出现 `**素材坐标**` |
| 6 | 已验算 | 出现 `**已验算**`（写清哪天、怎么跑的） |
| 7 | 证据与坐标区 | 出现 `## 证据与坐标` 小节 |
| 8 | 可验证主张 | 出现 `可验证主张` 块（供裁剪件原样裁出） |
| 9 | 讲师切分 | 出现 `**讲师 90 分钟**` 或 `讲师切分` |
| 10 | 尾注坐标 | 出现 `事实性句子坐标` |
| 11 | 习题 | 出现 `习题` |

> 说明：第 8 件在本卷原本写作「简历句框」。并仓时统一改为「可验证主张」：
> 开源仓里不发求职口径，且 `build_crops.py` 抽取主张块用的就是
> `> **可验证主张**` 这个词——按原设计本来就该这么叫。改的是术语，句子没动。

## 三、坐标的规格

坐标形如 `` `仓库@commit + 路径:行号` ``，例：

```
gen/adapters_kb.js:37
out/mc_all/README.md:18-22
```

规矩四条：

1. **代码按锚点读，书读工作树**（`tools/audit_coords.py` 实现）。
   书是活物，若书也按锚点读，书里对 `book/` 自身的引用会被拿上一版去核——核的是旧行号、报的是假结果。
2. **跨仓坐标必须标出来源**。本卷有少数坐标在兄弟仓（官方真值 CSV 在
   `forensics-mcopilot` 的 `knowledge/sdks/official_api/`、`KB7` 在 `axiscope`）。
   审计时行尾会标 `［跨仓:仓名］`，**不冒充本仓坐标**。
3. **跨仓锚要登记**。`tools/_anchor.py` 的 `FOREIGN_ANCHORS` 记着那两个仓的锚；
   结构门禁核对它们，锚写错（死指针）即判失败。
4. **仓外原件必须登记**。按设计不在仓内的文件，指针 + size + sha256 留在
   `evidence/REGISTRY.json`；没登记的「仓外原件」一律判失败——否则拼错文件名也会被放过。

## 四、裁剪件的规格

`crops/裁剪版.md` 是**生成物**，但它会被单独引用，所以有一道门盯着它：
`tools/verify_crops_verbatim.py` 要求裁剪件里每一段主张与切分都能在正文里**逐字找到**。
不一致即判红——因为它的样子与正文一模一样，读者分不出新旧。

**只有一件**裁剪件。原先有《可验证主张》与《讲师版》两份，并仓时合并，
理由写在裁剪件开头的「为什么只有一版」——那份理由本身也是规格的一部分。

## 五、门禁的规格

| 门 | 判什么 | 红了怎么办 |
|---|---|---|
| `audit_coords.py` | 每个坐标能否解析、行锚断言是否命中 | 改坐标或改正文，不许删坐标了事 |
| `check_book_structure.py` | 每章十件、导读件、前后言件、锚点一致 | 补件；锚不一致先改 `_anchor.py` 再改正文 |
| `verify_crops_verbatim.py` | 裁剪件与正文逐字一致 | 重跑 `build_crops.py` 或手改裁剪件 |
| `verify_book_numbers.py` | 书里自报的数字与实算一致 | 改数字，不许把断言删掉 |
| `scan_absolute_paths.py` | 家机路径 / 用户名 / 主机路径 / 脱敏标识值 | 清零或登记并披露 |
| `check_broken_links.py` | 书里引用的仓内路径是否存在 | 补齐或改成外链 |

**两条硬规矩**：

- **门禁匹配到 0 处即判失败**。一个匹配不到任何东西的门禁永远是绿的，
  那是「空转」而不是「通过」。
- **登记不等于放行**。登记项必须在书里披露；已清偿的登记项不再享受扫描豁免，
  值一旦回来立刻判红。

## 六、这一卷算完成的条件

1. 六道门禁全绿；
2. `crops/` 下只有一件裁剪件，且与正文逐字一致；
3. 每个坐标要么解析得到，要么是登记在册的仓外原件；
4. `known_findings.json` 里的每一条都在书里披露过；
5. 从**干净克隆**里跑一遍仍然全绿（不依赖作者机器的兄弟仓）。

第 5 条是最后一道，也是最容易自欺的一道：作者机器上兄弟仓都在位，
跨仓坐标当然解析得出来；换台机器就未必。所以「本地绿」不等于「读者能核」。
