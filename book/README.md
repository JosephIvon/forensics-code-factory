# 上位机代码工厂 · 电子书（与本仓代码同仓）

> 这是一本讲**怎么让每个技术主张都能被第三方当场核验**的书——
> 用一个真实的工业代码生成器做标本。
> 2026-10-24 起，电子书与本仓的代码**同仓**：一个 clone 就能拿到「书 + 一个能跑的案例仓」。
>
> **判断标准不是"哪本好看"，是"哪本的坐标能在这份代码里当场复核"。**
> 本卷的全部坐标都锚在 `trae_factory@954c210`，
> 也就是**本仓自己的某一次提交**上——读者手里没有它，坐标就只剩作者能核，
> 而"当场可核"正是这本书要证伪的那件事。

## 二、这一卷特殊在哪

三条，都不是修辞：

1. **只有四章**。别的卷九章，这卷四章。凑不出第五条就停——
   多写一章会把同一件事讲两遍，读者多花时间、判断反而更少。
2. **坐标跨两个仓**。第 2、3 章的核心论证（官方真值 CSV 在 `forensics-mcopilot`
   的 `knowledge/sdks/official_api/`；`KB7` 在 `axiscope`）本来就跨仓。
   审计时这类坐标会标出来源仓，**不冒充本仓坐标**。
3. **锚在本仓**。书搬进代码仓之后，`git show 954c210:<path>` 就能打开每条坐标——
   这是本卷唯一一条关于"书自己"的主张，由门禁每次运行现核。

## 四、怎么验

```bash
# 在仓根跑（不需要装任何依赖，只要 Python 3.9+ 与 git）
python book/tools/audit_coords.py            # 坐标能不能打开、行锚对不对
python book/tools/check_book_structure.py    # 每章该有的件是否齐、锚点是否一致
python book/tools/verify_crops_verbatim.py   # 裁剪件与正文逐字一致吗
python book/tools/verify_book_numbers.py     # 书里自报的数字与实算一致吗
python book/tools/scan_absolute_paths.py     # 公开前脱敏（家机路径/用户名/主机路径）
python book/tools/check_broken_links.py      # 书里引用的仓内路径存在吗
```

全部 exit 0 才算过。**有一道红就不许发**——这个仓的门禁设计原则写在
`OUTLINE.md` §五：门禁匹配到 0 处即判失败，登记项必须在书里披露。
