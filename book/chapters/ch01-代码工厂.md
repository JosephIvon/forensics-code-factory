## 1.1 概念：不手写代码，写"生成代码的代码"

多品牌上位机的老账：换一张卡，驱动层重写，业务层跟着改，文档与构建脚本各自腐烂。代码
工厂把顺序倒过来——工程师的产出物不是七套驱动代码，而是**生成器＋知识库**，卡相关代码
由机器批量生产：

> **生成器读知识库，批量产出"可编译骨架"：抽象层＋品牌适配器＋无硬件仿真＋
> 工艺样例＋双构建路径。换卡 = 改一个枚举。**

三条立场全在生成器原文里：**知识在文件里，不在模型里**——需求解析"规则式，零API依赖"
（index.js:28），同输入同产物、可复现可审计；**新品牌是一条枚举**——模板原文 `新增品牌 =
加一个枚举值 + 一个适配器 + 工厂注册一行`（core.js:35）；**完整度分级**——kbLevel：A 虚拟
全自研可运行 / B 官方真值核对 / C 骨架＋TODO（adapters_kb.js:19/:321/:668/:802/:857，
core.js:909-911）。

## 1.2 知识库的形状：一条品牌记录里存了什么

`gen/adapters_kb.js` 每品牌一条记录，以雷赛为例（:318-322）：id/dll/ns/cls 供代码拼接，
kbLevel 供文档分级，buildNote 存的是**坑**：

> 官方无软件使能接口(脉冲卡硬线使能)，使能项标注未实现。（adapters_kb.js:322）

三个结构点，一个比一个反直觉。**api 表每项带 chk（核对要点）**，指向官方 CSV 行号，如
`GT_Open(short channel,short param)（gts.csv:326 / gts_hdr.csv:367）`（:23）——知识库不是
名词表，是"这条签名凭什么信"的账本（跨仓机器核对是第 2 章的事）。**"未实现"是显式条目**：
固高 `官方 C# 绑定与 PE 导出表均无 GT_GetAi/GT_SetAo，已删除该臆造声明`（:37），雷赛软件
使能同款（:337）——**知识库的第一职责不是收录，是拒绝收录**。**C 级骨架的语义是"显式
失败"**：SDK 调用点全写成 `Fail(-300, "[TODO] …")` 指向《厂商手册》（adapters_kb.js:814-815），
自述 `骨架级——接口/单位换算/线程模型已就绪，SDK调用点以 [TODO] 标注并给出手册核对路径`
（:803）——不会的部分指路，不编能跑的假象。

知识库派生的核对清单头部有一段自我免责（core.js:924-926）：

> 本清单由生成器内置知识库派生，与适配器代码同源。它只能索引"去哪里核对"，不能证明
> 签名正确——签名若有错，错误会被原样列进清单。唯一有效依据是厂商官方手册/头文件。

生成器不为自己产出的签名背书——骨架式幻觉抑制的根：**幻觉防不住，但可以被标注、被删、被指路**。

## 1.4 换卡 = 改一个枚举：接缝落在哪一行

samples/Program.cs 生成时把接缝压到一行（core.js:676-677）：

```csharp
// ================== 换卡只改这一行 ==================
const Brand CREATE_BRAND = Brand.Virtual;
```

它喂给工厂：`工厂：业务层唯一的品牌耦合点。换卡 = 改调用处一个枚举值（JD职责3）`
（out/mc_all/src/Core/ControllerFactory.cs:12）。关键在**这个 switch 不是手写的**：factoryFile
从适配器列表逐条拼出 case 行（core.js:604-608），未注册品牌撞上 `default: throw new
NotSupportedException`（out/mc_all/src/Core/ControllerFactory.cs:25）。换卡成立靠三条纪律（out/mc_all/README.md:41-43）：
错误码统一映射 MotionResult、SDK 调用统一持锁、**单位换算集中在适配层，业务层只用用户
单位**（core.js:65）。但生成器同处留了句诚实话（core.js:679-680）：真实品牌的 P/Invoke 路径
**只做过编译级验证，未经运行验证**，切换前须按 docs/ApiChecklist.md 对照厂商手册核对签名
——换卡换的是接缝，不是责任：**枚举统一了七套驱动的"形"，"对"仍要靠上真机前的逐条核对**
（比对工时是上真机工作的主体，core.js:927）。

## 1.5 Virtual 层：无硬件的 CI 靠什么成立

VirtualController 与真实适配器实现同一接口（out/mc_all/src/Virtual/VirtualController.cs:15），
doc 注释印着用途三条：无硬件开发联调、单元测试与 CI 回归、工艺预演；`运动学为匀速段仿真 +
惰性推进（不占 CPU）；固定随机种子保证可复现`（:13，种子 12345 在 :38）。它不是空壳：反馈
位置叠加 2μm 噪声 `再现 SPC 统计场景`（:119-120），AI 通道 2.5V±0.08V 正弦＋噪声 `模拟压力/
胶量传感器`（:291-292），回零 ~1.2s（:135）——SPC 报表与 WaitHomeDone 在无硬件时都有东西可等。

两处细节说明这层仿真是**被认真对待的规格**：

- 参数守卫注释：越界必须返回 Fail，`不许靠深处异常冒泡、更不许沉默接受。真机适配器抄这里时
  必须保留同语义校验——越界轴号在真机上是非法内存访问（栈损坏级）`（:315-317）——虚拟层
  在给真机层立法。
- 它抓过真 bug：`[接缝3·BEH-15] 回零进行中不算已回零：不清此标志，WaitHomeDone 对已回零轴
  立即返回，重回零根本没等（行为断言抓到的真 bug）`（:133）；这组行为断言（BEH-01/03/04/
  07/09/14/15）随工艺样例每次运行自检（core.js:715）。

build_net48.bat 编译成功后立即运行虚拟 Demo（core.js:973-975）——`零安装`的全部含义：连厂商 DLL 都不需要，CI 每次提交都能跑完整流程。

## 1.6 实战案例：ACS 边界裁决（作者亲历）

ACS 在 BRANDS 表是正牌七分之一（index.js:16）、知识库里 B 级（adapters_kb.js:668），但有个
结构差异：不走 P/Invoke，直接 `using ACS.SPiiPlusNET;` 引官方托管库（:671），生成注释明写
部署条件——`build_net48.bat 需追加: /r:ACS.SPiiPlusNET.dll`（:684-686）。冲突在：全品牌套件
是**一个编译单元**，一条 csc 命令通编 src 全目录（core.js:972）——ACS 适配器一旦进套件，
没装 ACS 软件的机器上**整个套件编不过**，一张卡的依赖缺口劫持全部品牌。生成器原文裁决
（index.js:66-67）：

> ACS 不进全品牌套件：其适配器引用官方 ACS.SPiiPlusNET.dll，无该 DLL 时整个套件编不过；
> 选 ACS 作为目标品牌时仍单独生成专用套件

让边界不可褪色的是**派生机制**：全品牌适配器列表里根本没有 acs（index.js:65），于是工厂不
生成它的 case（core.js:604-608）、能力矩阵标 `B(需厂商DLL,不在全品牌套件)`（:906）并在 B 级
说明重复边界（:910）、样例注意块第三次提示（:681）。枚举值 `Acs = 4` 仍在 Brand.cs
（core.js:42），但适配器类不在套件里，误用会撞运行时 `NotSupportedException`
（out/mc_all/src/Core/ControllerFactory.cs:25）。真正的 ACS 用户单独生成专用套件，构建脚本届时自动追加 `/r:`
指引（core.js:960-963）。代价：`全品牌`名下缺一家、ACS 用户多一步装官方软件——用字面遗憾
换另外五品牌**开箱必编译**的硬承诺。边界不写进生成器原文，下次再生就会被遗忘；文档可以
跳过不读，代码不会。

## 1.7 习题

**知识题**

1. 需求解析为什么做成"规则式，零API依赖"（index.js:28）？牺牲了什么？
   *参考*：换来同输入同产物、可复现可审计，知识全部来自文件；牺牲自然语言覆盖面（词表外
   说法解析不出）。工业生成器里，确定性比聪明值钱。
2. "已删除该臆造声明"为什么不从 api 表悄悄消失，而要留 ok:false 记录（adapters_kb.js:37/:337）？
   *参考*：留痕把"此路不通"变成知识库的一部分，下一个人不再发明同一臆造；且计入清单总 n
   不计入 k（core.js:931），账面持续可见——悄悄删除=坑被反复挖开。
3. 工厂的 switch 是拼出来的不是手写的（core.js:604-608），这决定了什么？
   *参考*：适配器列表成为单一来源，工厂 case、能力矩阵、核对清单全派生自它——ACS 边界一处
   裁决自动传导到所有生成物；手写工厂每次加品牌改两处，漏改即债。

**反事实题**（参考答案=真实裁决，含代价）

4. 让生成器直接产出"完整实现"而非骨架，质量会更好吗？
   *参考*：不会。B 级仍有单位/量程/IO 极性等待核项（core.js:910），"补全"只能靠编；两处"已
   删除臆造声明"（adapters_kb.js:37/:337）证明官方真值没有的函数，一"补"即幻觉。骨架把不知道
   落成显式失败并指路手册（adapters_kb.js:814-815），完整实现把未核对状态埋进"能编译能启动"
   的假象，首次真机异常才发现签名是编的——排查的是栈损坏级故障（out/mc_all/src/Virtual/VirtualController.cs:317）。
   代价：骨架把成本放在按清单逐条核对（上真机工作的主体，core.js:927），完整实现把成本转成
   现场排障——贵一个数量级且不可排期。
5. 如果没有 Virtual 层，无硬件的 CI 会怎样？
   *参考*：CI 失去宿主。build_net48.bat 编译完立即运行 Demo（core.js:973-975），Demo 默认
   CREATE_BRAND=Brand.Virtual（core.js:677）——没有 Virtual，"30 秒跑起来"只剩编译半个动作，
   运行要么缺厂商 DLL 直接崩、要么排队等插真卡的工控机，回归退化成"有卡才跑"；BEH-15 类
   回归（out/mc_all/src/Virtual/VirtualController.cs:133）失去无硬件复现场所，SPC 样例失去 2μm 噪声数据源
   （:119-120）。代价：仿真有保真度硬边界（匀速段＋惰性推进，:13）——Virtual 绿灯只证明
   流程接线正确，当真机绿灯是另一种自欺；且抽象层少一面镜子（第二实现会逼出泄漏的品牌细节）。
