## 2.1 概念：生成器写的每一行"事实"都是主张

代码工厂批量产出的 C# 适配器里，最危险的不是逻辑错误（那个编译器和测试会抓），
而是**签名**——`[DllImport("gts.dll")] static extern short GT_Axis(...) ` 里每个
类型、每个参数个数，都是对厂商官方接口的一条**主张**。LLM 时代的生成器让主张的
产量乘了一百倍，也让"看起来对"的签名可以以假乱真：参数个数对了、名字像真的、
编译照样通过——直到真机上一调用，栈就坏了。

《协议域卷》第 2 章讲过三态真值：真/假/悬置。本章给出它的**生成器版**：

> **真值链 = 给每条主张挂三根轴（源｜核对｜提取），让"这条签名凭什么信"
> 变成代码里可审计的一行注释，而不是生成器的一次沉默。**

## 2.2 三根轴与唯一事实源

`gen/truth_kb.js` 头注（:5-9）把设计原则写成原文：

```
源   = verified  ：这条结论从哪来（官方手册/官方绑定/公开资料/未标注）
核对 = check     ：验到哪一步（manual 人工核对 / hardware 真机 / auto 机器比对 / none 未核对）
提取 = extraction：签名对是否等于调用对（judgment = 有语义陷阱；mechanical = 机械可复核）
本模块只【标注与报告】，不改写任何签名 —— 两边口径不一致时显式列出，人工裁决，
绝不悄悄选边（谁都不是第三个事实源：唯一事实源是 mcopilot knowledge/sdks 的官方绑定行号）。
```

四个设计点，每个都在防一种具体的自欺：

1. **"绝不悄悄选边"**：工厂口径与知识库口径不一致时，生成物里打上
   `【口径不一致·用前必须人工裁决】`（truth_kb.js:170）——裁决权留给人，
   机器的职责是把不一致**变得无法视而不见**。
2. **"谁都不是第三个事实源"**：知识库发现顺序是 `MCOPILOT_ROOT 环境变量 →
   本机默认路径 → 整体降级`（:11），工厂**实时读取** mcopilot 的绑定行号，
   不另设副本——副本一旦存在，就会悄悄长成第二个事实源。
3. **"找不到则降级，生成不中断"**：知识库不可达时，全部签名按
   `[ 源 未标注 | 核对 none | 提取 judgment ]` 处理并打 TODO（:196）。
   降级不是隐瞒——是**把无知写成显式状态**。
4. **TODO 的闭环指向源仓库**：降级和未核对条目的 TODO 写的是
   "核对后更新 **mcopilot** 仓库 knowledge/sdks/*.json 并重跑
   annotate_provenance.py --check，**然后重新生成本套件**"（:91-92）——
   修正永远发生在事实源那一侧，工厂侧只负责继承。

## 2.3 动手：看一条真值链长什么样

```powershell
$env:MCOPILOT_ROOT='<你的工作区>\mcopilot'; node test_gen.js gts   # 单品牌再生
```

生成后的适配器（`out/mc_gts/src/Adapters/GoogolGtsController.cs:63`）：

```csharp
// [ 源 official-binding | 核对 none | 提取 judgment ]  导出表无背书
[DllImport("gts.dll", ...)]
private static extern short GT_SetTrapPrm(...);
```

同批产物 `docs/TruthChain.md` 是逐条对照表（gts 品牌段实录）：

> P/Invoke 22 条：钉扎 19 / 未收录(降级) 3 / 口径不一致 0；
> **核对进度 manual 0 / hardware 0 / auto 0 / none 19**

看清楚这行账：**钉扎 19 ≠ 核对 19**。钉扎只说明"这条签名在知识库里有出处可查"，
`none 19` 诚实承认"19 条还没人验过"——它们在生成代码里全部带
`TODO[需核对厂商手册]` 标记。真值链的职责是让验证进度**可计数**，不是替你
把验证做掉。

## 2.4 跨仓验证门：三层官方真值对撞

真值链是工厂侧的自我标注；`mcopilot/scripts/verify_trae_pinvoke.py` 是
**源仓库侧的独立对撞**——它扫工厂产物里每条 `[DllImport]`，拿三层官方真值
裁决（脚本头注 :11-16）：

1. **DLL PE 导出表**：`已导出=1` 才可调用，`=0` 表示"符号在但没导出"；
2. **厂商官方 C# 绑定**（zmotion.csv / gts.csv / leisai.csv）；
3. **官方 C 头文件**（zmotion_cpp.csv / gts_hdr.csv / leisai_cpp.csv）。

三态判定只有一条判据——**官方真值里存在**（:18）：

| 状态 | 判据 | 含义 |
|---|---|---|
| 双绿 ok | 导出表已导出 + 官方绑定存在 | 可信 |
| 需自证 needs_proof | 仅导出表有 | 签名只能自己从 PE 侧自证，人工确认 |
| 不可用 missing | 三层皆无 | 典型：函数名臆造，或 DLL 名写错 |

两个精度细节，都是踩过坑才会写出来的：

- **C 的 long 在 Windows 是 32 位（LLP64）**。返回类型比对优先用
  **厂商官方 C# 绑定**的返回类型层（binding_returns.csv），理由写在
  :154-161："C 头文件是 C 语言，拿 C# 声明去比 C 头文件的返回类型会口径错位
  （雷赛 LTDMC.cs:891 把 C 的 long 映射成 Int32）"。
- **函数名匹配用规范化精确匹配，不用 `\b` 词边界**（:40-41）——
  `GT_SetTrapPrm` 里下划线是单词字符，词边界正则会漏配。

2026-10-22 当日实跑（收尾停机点产物）：

```
声明总数(去重) : 58   (文件内出现次数 116)
双绿(ok) 58 ｜ 需自证 0 ｜ 不可用 0
参数签名 MATCH 58 ｜ 返回类型一致 58
⚠ 变体间参数表冲突(单卡/多卡同DLL同符号) : 22 条
--strict 退出码 0
```

注意最后那行 ⚠：22 条**变体冲突**被报告出来但**不判死**——同一 DLL 同一符号
在单卡/多卡变体间参数表不同，是厂商自己的历史包袱，工具的职责是把它显式记账，
不是替你裁决哪个变体"正确"。

## 2.5 实战案例：一条死路径债的完整生命周期

作者亲历，2026-10-22 收尾日：

1. **债的形成**：truth_kb.js 的本机默认路径（:24）写着另一场战役已消亡的
   会话工作区地址——知识库文件搬了家，工厂不知道。与 mcopilot 自己的
   搬仓债（《协议域卷》§3.5 案三）同款：**路径是隐式契约，搬家即违约**。
2. **发现**：收尾盘点时跨仓核对路径（mcopilot `0cfc358` 清偿同类债的先例
   提示了去查同类位置）。
3. **清偿**：默认路径改指 `%WORKSPACE%\mcopilot`（trae 收尾提交 `2da4559`），
   全品牌再生验证退出码 0。
4. **止损审计**：死路径期间生成的产物带着**降级真值链**——这不是静默坏账，
   决策清单把它记为未结清项 C2（"五品牌 TruthChain 完整度未逐份复核"），
   当日逐品牌再生清偿（`954c210`）：gts 19/22、雷赛 13/16、正运动 17/20 钉扎
   （高川/软赢 0 条 P/Invoke，无真值链可挂属设计事实）。

整条生命周期能走通，靠的是 §2.2 第 3 条：**降级是显式状态**——如果死路径
期间工厂假装一切正常，债就无声了。

## 2.6 账必须平：未收录与未核对是两本账

truth_kb.js:151-152 有一段值得抄进任何统计代码的注释：

> 未收录降级不进 noneList —— "未核对"专指钉扎了但 check=none 的条目，
> 降级条目已在 missed 里单独统计，**重复计入会让总汇总 56+2+2=60 这种账对不上**。

"未收录"（知识库没有这条）和"未核对"（有出处但没人验过）是两个正交状态，
混在一个桶里，汇总数字就再也对不上真值链总数。**当账面可能对不上时，错的
从来不是账本，是分类学。**

## 2.7 习题

**知识题**

1. 三根轴里"提取 = judgment"为什么单独存在？"签名对"和"调用对"差在哪？
2. 为什么 TODO 让你去 mcopilot 仓库改 JSON，而不是直接改工厂里的副本？
3. 22 条变体冲突为什么不判死？如果判死会发生什么？

**反事实题**（参考答案=真实裁决，含代价）

4. 死路径期间生成的产物，错在哪里、怎么发现、怎么止损？
   *参考*：错在默认路径指向已消亡的会话工作区（`truth_kb.js:24` 旧址），产物
   带降级真值链而无从察觉——若非降级是显式状态（[ 源 未标注 ]直接印在代码里），
   债将无声。发现靠收尾盘点的跨仓路径核对（同类债 `0cfc358` 先例提示）；
   止损靠修复+全品牌再生+决策清单记未结清项 C2（清偿 `954c210`）。代价：再生
   时点混排（部分套件为修复前生成）需如实登记。
5. 让生成器直接产出"完整实现"而非骨架+真值链标注，会更好吗？
   *参考*：不会——完整实现把主张的数量再翻几倍，而每条主张都需要核对成本；
   骨架+TODO 把"哪些签名还没验"变成可计数清单（gts none 19 一目了然），
   完整实现则会把未核对状态埋进"能跑"的假象里。真值链的对象是**主张的账**，
   不是代码的美观。
