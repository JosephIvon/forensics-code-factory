# 尾声：把账算完

> 一本书最容易骗人的地方是结尾。开头许诺「每个主张都能核」，结尾要么不再提，
> 要么用一句「相信读者已经体会到」收场。这一节把账算完：
> **哪些结论站得住、哪些是没做而不是没做成、哪些是这本书根本不打算做的。**

## 一、这本书立住了什么

四条结论，每条都能被读者当场验：

**1. 生成器可以只产骨架，而不假装产实现。**
`gen/index.js` 与 `gen/adapters_kb.js` 里，凡是知识库没有的 API，生成出来的就是
显式 TODO 骨架 + 清单，不是「猜一个」。两个品牌 0 条 P/Invoke 时，
产出的是骨架 + TODO，而不是把 0 粉饰成「齐全」（第 3 章 §3.6）。
坐标：`trae_factory@954c210 gen/adapters_kb.js`。

**2. 「每条签名都是主张」是可以落成机制的。**
生成器侧按 [源｜核对｜提取] 三轴逐条标注；源仓侧用三层官方物证（PE 导出表 /
官方 C# 绑定 / C 头文件）独立对撞。58 条 P/Invoke 全双绿、签名与返回类型全 MATCH，
用一条命令就能复跑（第 2 章 §2.4、§2.3）。
坐标：`trae_factory@954c210 gen/truth_kb.js`。

**3. 收尾可以是一个有判据的过程，而不是「感觉差不多了」。**
R1 四件套（同步文档 / 处置未提交 / 决策清单 / 明确停机点）把「悬着」逼成三类：
入库、忽略、挂起。71 条在途改动逐条裁决，收尾后 0 未提交（第 4 章 §4.2–§4.3）。
坐标：`book/decision-lists/trae_factory-2da4559.md`（已入库 vendored 件）。

**4. 书与代码可以同仓同锚。**
这是本卷 2026-10-24 的那次搬迁要证的事：读者 `git clone` 本仓，
`git show 954c210:<path>` 就能把书里每条坐标打开。
**这条是本卷唯一一条关于「书自己」的主张**，也是最容易被糊弄的一条——
所以它由 `book/tools/audit_coords.py` 每次运行现核，不靠信。

## 二、哪些是「没做」，不是「没做成」

这两句必须分开写，否则读者会把「挂起」误读成「已完成」：

| 项 | 性质 | 依据 |
|---|---|---|
| **真机层验证** | **设计性挂起**（不是没做成） | 判据是量程边界：没有真机就不存在「真机已验证」这个事实；仓里把这条挂起登记在案，而不是标成待办 |
| **高川 / 软赢 0 条 P/Invoke** | **已交付骨架 + TODO**（不是漏做） | 官方三层物证里查不到可用符号，硬写就是臆造；选择交骨架并写明缺什么 |
| **7 份协议标准与厂商手册原件不在仓内** | **外置**（不是丢失） | 仓内只留指针 + size + sha256；原件按需取用，原件不在位时相关核对记 SKIP 并写明「当前不可自动复核」 |
| **迁居凭证（B3）** | **冻结登记**（不是放行） | 迁居到仓外的素材凭证据已冻结，逐件可查；不删、不假装已清 |

最后一行值得多说一句：**「记在账上」不等于「已清偿」**。
本卷的门禁里有一条专门防这件事——登记项必须同时在书里披露，
否则登记表就退化成了沉默的白名单（白名单是假绿的另一种写法）。

## 三、这本书不打算做的事

- **不写 API 手册**。要查某个函数怎么调，读代码比读这本书快。
- **不写厂商适配教程**。五家品牌的差异是工程细节，写进书里三天就过期。
- **不评价别家的仓库**。第 4 章里出现 axiscope，是因为那是同一个人的双仓收尾案卷，
  不是横向评测。
- **不预测这套方法能不能推广**。书里只说这个仓里它是怎么做的、代价是什么。

## 四、这本书自己的账

写这本书的过程里，最值得记的不是写了什么，而是**改过什么假话**：

1. 曾有句「门禁全绿」在门禁匹配到 0 处时照样显示绿——**空转被当成了通过**。
   现在那条自检有一条硬规定：**匹配到 0 处即判失败**。
2. 曾有引用的行号在源文件变动后失效，而门禁只查「文件在不在」，不查「那一行
   说的是不是那句话」——**存在不等于正确**。现在坐标审计逐条比对内容。
3. 曾有登记项在书里没有披露，登记表成了白名单。现在每条登记都要在书里出现。

这三条都是同一个错误的不同形状：**让「没有失败」代替「验过了」**。
这本书对读者的全部承诺，归根到底就是不让这三件事再发生。

还有一条是**并仓时新冒出来的**，值得单记：本卷搬进代码仓那一刻，它从「不对外发布的书」
变成了「公开仓的一部分」，于是原来扫不到的东西第一次被扫到——

**K-1（本机工作区路径，已清偿）**：正文的一条示例命令、一处清偿叙述、以及入库的决策清单，
共 3 处写着作者本机的工作区绝对路径。这些值在书仓里不算问题（书仓不发布），
搬进来就是问题。处置是等行内替换为占位符，3 处清零。
教训不是「要脱敏」，而是：**搬家会改变一件东西的暴露面，而搬运动作本身不会提醒你这件事。**
登记与处置记在 `book/known_findings.json`（K-1），脱敏门每次运行都会现扫一遍。

这条同时也暴露了一处**口径缺口**，一并记在这里：本仓脱敏门**没有「绝对墙钟」这一档**。
`out/mc_all/README.md` 这类生成物里带着生成时刻，它不是上游数据集的时钟、
也不是本机时间，但它确实是一条墙钟。补这一档是独立工作，**本卷没做**，故披露而不假装已扫。

## 五、如果要接着往下做

留给后来者的三件（不是本书的欠账，是这套工程自然的下一步）：

1. **真机层**：一旦有真机，把挂起的验证按 R1 四件套重新开一轮，
   而不是在旧结论上打补丁。
2. **更多品牌**：新增品牌时先补知识库条目与三层物证对撞，再动生成器——
   顺序反了就会先有代码后有真值。
3. **门禁扩面**：本卷门禁目前覆盖坐标、结构、裁剪件与自报数字；
   再往下该覆盖的是「生成物与 gen/ 同源」这类**漂移**检查。
